\section{GitOps Deployment Với ArgoCD Và Kustomize}
\label{sec:gitops}

\subsection{Kiến trúc repo GitOps}

Repo \texttt{gitops-manifest-k8s} được tách khỏi repo mã nguồn YAS và đóng vai trò nguồn chân lý cho trạng thái triển khai. Cách tổ chức này phân tách vòng đời build ứng dụng với vòng đời cấu hình Kubernetes, đồng thời lưu lại lịch sử thay đổi image tag và manifest bằng Git. Thư mục \texttt{base} chứa Deployment, Service và ServiceAccount dùng chung; các thư mục \texttt{environments/dev}, \texttt{environments/staging} và \texttt{environments/developer-build} chứa cấu hình riêng cho từng môi trường.

\subsection{Base manifest và phạm vi workload}

Mỗi workload ứng dụng được mô tả bằng các tài nguyên Kubernetes độc lập. Nhãn \texttt{app} và \texttt{serviceAccountName} được chuẩn hóa theo tên workload để hỗ trợ selector, định tuyến và Istio AuthorizationPolicy. \subsection{Kustomize overlays}

Overlay \texttt{dev} kết hợp \texttt{base}, \texttt{location}, \texttt{kafka-connect}, cấu hình connector và các chính sách Istio. Các patch được dùng để điều chỉnh host, chiến lược rollout và cấu hình riêng của UI mà không sao chép toàn bộ manifest. Image của từng workload được khai báo trong trường \texttt{images}; theo luồng CD, Jenkins cập nhật \texttt{newTag} bằng short commit SHA sau khi build và push image thành công.

Các patch dependency tương ứng cũng trỏ workload thử nghiệm tới hạ tầng dùng chung ở \texttt{dev}, qua đó hạn chế nhân bản thành phần dữ liệu.

\subsection{ArgoCD đồng bộ trạng thái triển khai}

ArgoCD theo dõi repo GitOps và đối chiếu desired state với trạng thái thực tế trong cluster. Khi Jenkins commit image tag mới, ArgoCD phát hiện thay đổi và biểu diễn sai lệch bằng trạng thái \texttt{OutOfSync}. Stage \texttt{Update GitOps --- Dev} chạy sau pipeline thành công trên branch \texttt{main}; stage \texttt{Update GitOps --- Staging} chạy khi commit tại HEAD có release tag dạng \texttt{vX.Y.Z}. Ảnh chụp staging ghi nhận thời điểm ứng dụng vẫn \texttt{Healthy} nhưng desired state mới chưa được đồng bộ; do đó ảnh này minh chứng khả năng phát hiện sai lệch của ArgoCD, không được dùng để khẳng định rollout staging đã hoàn tất. Pipeline không áp dụng trực tiếp manifest ứng dụng bằng \texttt{kubectl apply}; quyền hội tụ trạng thái thuộc về ArgoCD.

\subsection{Luồng triển khai end-to-end}

\begin{enumerate}
\item Developer push code lên GitHub.
\item Jenkins Multibranch Pipeline phát hiện thay đổi và thực hiện kiểm thử, quality gate và security scan.
\item Jenkins build Docker image, push lên registry với tag là short commit SHA.
\item Jenkins cập nhật image tag và tạo commit trong repo GitOps.
\item ArgoCD phát hiện commit mới và đồng bộ overlay vào namespace tương ứng.
\item Kubernetes rollout workload; readiness probe và trạng thái ArgoCD xác nhận kết quả triển khai.
\end{enumerate}

Thiết kế này tạo chuỗi truy vết từ commit mã nguồn, image trên registry, commit manifest đến revision đang chạy trong Kubernetes. Kustomize giảm trùng lặp cấu hình giữa các môi trường, còn ArgoCD duy trì cơ chế đồng bộ và phát hiện sai lệch trạng thái.
